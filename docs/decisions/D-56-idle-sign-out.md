# D-56: No lock screen: 10 idle minutes sign you out (Nov 3, 2026)

**Decided by the owner.** After the app locked, the owner had to tap Unlock and then sign in again. Locking already ended the sign-in on the server (13.4), so "locked" only chose which screen came next, and that choice raced: the app ended the sign-in and checked it again at the same moment. If the check got there first, the Lock screen showed while holding a sign-in the server had already ended, and the next check of it dropped to Sign in. If the sign-out got there first, Sign in showed with no Lock screen. With the Worker and a fake clock, 2 of 3 runs after 11 minutes in the background showed Sign in. The owner asked to drop the lock idea everywhere, including Settings → Sign-in.

1. **10 idle minutes, or 10 minutes in the background, sign you out.** The keys, the copy in memory and the screens go, and the sign-in ends (`signOutIdle`, `endSignIn` in `apps/web/src/copy/copy.ts`). The sign-out finishes before the app checks the session again, so the app always shows Sign in. That one Face ID also returns the PRF output, which opens the saved copy, so it still downloads only what changed. A refresh within 10 minutes still reopens without Face ID (held key, unchanged).
2. **Opening with a sign-in that's still valid but no Face ID** (the app was closed in the background past 10 minutes) ends that sign-in too and shows Sign in, instead of a Lock screen.
3. **No signal** keeps its own screen: "No signal", **Open with Face ID** opens the saved copy for up to 7 days, as before (13.6). It's the only screen left in `screens/Copy.tsx` besides getting ready and couldn't open.
4. **A fresh sign-in whose passkey gives no PRF output** (or a different salt) opens the budget in memory for the visit and leaves the saved copy for the next sign-in, instead of asking again.
5. **Settings → Sign-in lists only live sign-ins.** A device that's signed out with the budget saved on it is no longer a row ("Locked since …" is gone, and `locked` is gone from `SecurityView`). "Sign out other devices" still turns those copies off and now shows whenever there's any such device, so a lost phone can still be wiped. Signing out one listed device is unchanged.
6. The lock screen's "Sign out and delete it from this phone" went with it: sign in, then Settings → Sign-in → Sign out of this device.

Replaces the Lock parts of `docs/phone-budget.md` 13.4 and 16, and D-52 items 1 and 4 (the locked row and the lock screen button). The status is `signed_out` in code; the held-key IndexedDB database keeps its name (`ledgerline-unlock`) so keys already held still work.
