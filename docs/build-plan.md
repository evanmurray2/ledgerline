- [ ] Phase 5, the sealed log (`docs/privacy.md` 5.3). A copy as chunks and table hashes (`apps/worker/src/local/device-snapshot.ts`). A device writes a snapshot of its base and reads it back, a new device opens one and goes on from the log, and a device checks the newest one by rebuilding the budget from the one before plus the entries since (`writeSnapshot`, `openSnapshot`, `checkSnapshot` in `device-snapshot.ts`; `test/snapshot-flow.test.ts`); the fetch backstop runs the delete rule; `GET /api/log/public` gives the public entries a new device walks. A snapshot's first line lists its writer's columns, so a copy on another version of the app opens it or says "update". Each change a device makes has one entry id (`entryIdOf`), so a change sent again after a lost answer is in the log once and the device knows its own entry; a device's place in the log is kept with its copy (`DeviceLog.save`, `restore`).
