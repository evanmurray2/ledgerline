# API

The Worker serves the SPA and a JSON API under `/api`. Every request needs a signed-in session (passkey sign-in, decisions.md D-27): an HttpOnly cookie whose SHA-256 the Worker looks up in `auth_session`. The sign-in routes and the Plaid webhook are the only public ones. Linking or repairing banks, exports and passkey changes need a passkey check within the last 15 minutes, or they return `401 { error: "reauth" }`. The GitHub monitor and the deploy smoke test use `Authorization: Bearer <OPS_TOKEN>`, which reaches only the health endpoint. Mutations (`POST`, `PUT`, `PATCH`, `DELETE`) require `content-type: application/json`, the header `x-ledgerline: 1` and a same-origin `Origin`. Schemas and types are in `packages/contracts`. Money is integer cents; months are `YYYY-MM`; a date sent is a real calendar date `YYYY-MM-DD`. A month or date more than 10 years from this month is refused (`422 too_far` for a change, `400` for a screen): the phone works out every month up to the last one with data. A sync page's `limit` is 1–500 (200 otherwise), and a cursor the server didn't write is a `400`. Every answer is JSON, unknown paths and methods included (`404 not_found`).

**Screens are worked out on the device (D-45).** The app's engine (`apps/worker/src/local`) answers every screen read below from the copy it syncs with `GET /api/sync`, using these same routes. On the server, those reads answer `404 { error: "on_device" }`; the server still answers the session, sync, bank connections, Settings → Sign-in, exports and health. Changes still go to the server, which answers `{ ok: true }` without `rta`; the app fills Ready to Assign from the copy after syncing the change.
