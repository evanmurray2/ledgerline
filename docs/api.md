# API

The Worker serves the SPA and a JSON API under `/api`. Every request needs a signed-in session (passkey sign-in, decisions.md D-27): an HttpOnly cookie whose SHA-256 the Worker looks up in `auth_session`. The sign-in routes and the Plaid webhook are the only public ones. Linking or repairing banks, exports and passkey changes need a passkey check within the last 15 minutes, or they return `401 { error: "reauth" }`. The deploy smoke test uses `Authorization: Bearer <OPS_TOKEN>`, which reaches only the health endpoint. Mutations (`POST`, `PUT`, `PATCH`, `DELETE`) require `content-type: application/json`, the header `x-ledgerline: 1` and a same-origin `Origin`. Schemas and types are in `packages/contracts`. Money is integer cents; months are `YYYY-MM`; a date sent is a real calendar date `YYYY-MM-DD`. A month or date more than 10 years from this month is refused (`422 too_far` for a change, `400` for a screen): the phone works out every month up to the last one with data. Every answer is JSON, unknown paths and methods included (`404 not_found`).

**Every budget is locked (D-102).** The routes of the table that read or change the budget run only on the device, in the app's engine (`apps/worker/src/local`), over the device's own copy; the copy lives on the budget's sealed log (`/api/log/*`, `apps/worker/src/seal/log-routes.ts`). The server answers sign-in, Settings → Sign-in, the bank links by id, Fetch now, the Plaid webhook, health and a new budget's start (`/api/start/*`: `begin` answers with a start id that its chunks and its seal must name); any other path is `409 { error: "sealed", message: "Update Ledgerline to continue." }`.
