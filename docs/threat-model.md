# Threat model

| Asset                            | Threat                               | Control (where)                                                                                                                                                                                                                                   |
| -------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Financial data in D1             | Anyone reaching the Worker           | Cloudflare Access on the whole hostname, plus the Worker's own Access JWT check on every API request (`apps/worker/src/http/auth.ts`); membership check and budget-scoped queries (`src/db/scoped.ts`)                                            |
| Plaid access tokens              | Leak from D1, logs or API            | AES-256-GCM with a Worker-secret key and per-row key version, bound to the connection id (`packages/platform/src/token-crypto.ts`); decrypted only in sync steps and Link repair; never returned by any endpoint; logs use an allowlist of fields |
| Webhook endpoint (Access bypass) | Forged webhooks triggering work      | ES256 `Plaid-Verification` JWT, key by `kid`, 5-minute `iat`, body SHA-256 (`packages/bank-provider/src/plaid.ts`); the handler only starts a sync for a known Item                                                                               |
| Browser session                  | CSRF, clickjacking, script injection | JSON content type + `x-ledgerline` header + same-origin `Origin` on mutations; CSP allowing only self and Plaid Link; `frame-ancestors 'none'`; `Referrer-Policy: no-referrer`; HSTS                                                              |
| Production Plaid keys            | Exposure to unreviewed code          | Only in the production Worker's secrets; staging is a separate Worker; PR workflows get no Cloudflare token; production deploys need your approval                                                                                                |
| Plaid Items (10 for life)        | Burning slots by mistake             | Sandbox everywhere but production; update mode for repairs; Item meter and confirm step; server refuses a new link at 10                                                                                                                          |
| Bank history                     | Tampering                            | `bank_event` and `bank_page` reject UPDATE and DELETE (triggers); raw pages in R2 with a server-side checksum recorded per page                                                                                                                   |
| Backups                          | A compromised CI reading them        | Encrypted to an age public key; the private key is offline; 90-day retention; monthly restore drill                                                                                                                                               |
| Availability                     | D1 daily limits take the app offline | Account-wide usage from GraphQL Analytics; the breaker pauses background work at 70% and makes the app read-only at 90%                                                                                                                           |
| Supply chain                     | Malicious dependency or action       | Lockfile, Dependabot, OSV-Scanner, dependency review, actions pinned to commit SHAs, zizmor and actionlint                                                                                                                                        |

Accepted: a compromise of your Cloudflare account or your identity provider (GitHub) exposes the data. Hardware-key 2FA on both is the main mitigation.
