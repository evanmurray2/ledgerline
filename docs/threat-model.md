# Threat model

| Asset                     | Threat                                                             | Control (where)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Financial data            | Anyone reaching the Worker                                         | Passkey sign-in verified by the Worker (`apps/worker/src/routes/auth.ts`, decisions.md D-27); every API request needs a server-side session in the Directory (`src/http/auth.ts`, `src/store/router.ts`), and the Worker opens only the signed-in user's own BudgetStore (one SQLite Durable Object per budget, D-37); budget-scoped queries (`src/db/scoped.ts`). Only sign-in and the Plaid webhook are public.                                                                                                                                                                                                                                           |
| Sessions                  | Theft or replay                                                    | Random 256-bit token in an HttpOnly, Secure, SameSite=Strict `__Host-` cookie; the database stores only its SHA-256; 24-hour absolute expiry; "Sign out other devices" deletes the rows. Linking banks, exports and passkey changes need a passkey check within 15 minutes.                                                                                                                                                                                                                                                                                                                                                                                 |
| First sign-in             | Someone else registering first                                     | The first passkey needs `SETUP_CODE` (a Worker secret, 32+ characters, constant-time compare), which stops working once a passkey exists. Added devices need a single-use 10-minute link from a signed-in device. WebAuthn challenges are single-use, stored server-side for 5 minutes; origin, RP id and user verification are checked.                                                                                                                                                                                                                                                                                                                    |
| Ops endpoint              | Token leak                                                         | `OPS_TOKEN` reaches only `GET /api/health` (statuses, no financial data); constant-time compare; kept in GitHub environment secrets.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Plaid access tokens       | Leak from the database, logs or API                                | AES-256-GCM with a Worker-secret key and per-row key version, bound to the connection id (`packages/platform/src/token-crypto.ts`); decrypted only in sync steps and Link repair; never returned by any endpoint; logs use an allowlist of fields                                                                                                                                                                                                                                                                                                                                                                                                           |
| Webhook endpoint (public) | Forged webhooks triggering work                                    | ES256 `Plaid-Verification` JWT, key by `kid`, 5-minute `iat`, body SHA-256 (`packages/bank-provider/src/plaid.ts`); the handler only starts a sync for a known Item                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Browser session           | CSRF, clickjacking, script injection                               | JSON content type + `x-ledgerline` header + same-origin `Origin` on mutations (sign-in routes included); SameSite=Strict cookies; CSP allowing only self and Plaid Link; `frame-ancestors 'none'`; `Referrer-Policy: no-referrer`; HSTS                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Production Plaid keys     | Exposure to unreviewed code                                        | GitHub `production` environment secrets, uploaded to the production Worker on each deploy (D-28); the environment requires your approval and isn't available to pull requests; staging uses Sandbox keys; the deploy token in the same environment could already read them through a deployed Worker, so this adds no new path                                                                                                                                                                                                                                                                                                                              |
| Plaid Items (10 for life) | Burning slots by mistake                                           | Sandbox everywhere but production; update mode for repairs; Item meter and confirm step; server refuses a new link at 10                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Bank history              | Tampering                                                          | `bank_event`, `bank_page` and `raw_page` reject UPDATE and DELETE (triggers). Raw pages live in the budget's store next to the events (D-26, D-37), so this guards against application bugs, not against someone with write access to the store.                                                                                                                                                                                                                                                                                                                                                                                                            |
| Copy on the phone (D-45)  | A stolen or borrowed phone; a script in the page; a revoked device | Kept on an iPhone or iPad only (Safari or the Home Screen app, D-48), as one AES-GCM blob whose data key is wrapped under HKDF(passkey PRF output ‖ a per-device share the Directory holds); keys are non-extractable and in memory only; lock after 10 idle minutes or 10 minutes in the background, which also ends the server session; wiped on sign-out, `not_member` or a revoked device; offline unlock for 7 days after the last sign-in (`apps/web/src/copy`, `docs/phone-budget.md` 13). Accepted (owner, D-45): someone with the passkey who keeps the phone offline keeps the last snapshot; a script running while unlocked reads what you can. |
| Data loss                 | Damage noticed late, or losing the Cloudflare account              | No off-site backup, by the owner's choice (D-29). Point-in-time recovery on each Durable Object (30 days, D-37) covers recent mistakes; the full backup on Import and export, kept yourself, covers the rest. Accepted risk: anything older than 30 days that isn't in a backup.                                                                                                                                                                                                                                                                                                                                                                            |
| Availability              | Daily free limits take the app offline                             | Account-wide usage from GraphQL Analytics; the breaker pauses background work at 70%, makes the app read-only at 90% and stops reading at 95% (D-40), counting Durable Object and Worker requests too; past the Durable Object daily allowance the app says so plainly until 00:00 UTC                                                                                                                                                                                                                                                                                                                                                                      |
| Supply chain              | Malicious dependency or action                                     | Lockfile, Dependabot, OSV-Scanner, dependency review, actions pinned to commit SHAs, zizmor and actionlint                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Accepted: a compromise of your Cloudflare account exposes the data and the secrets. A compromise of a device with your passkey (unlocked) can sign in. Hardware-key or passkey 2FA on Cloudflare, GitHub and Plaid is the main mitigation.
